## 2. 保留的业务与页面

- 管理员、读者分角色登录；读者注册、资料校验、冻结与解冻。
- 图书检索、新增、增加副本、停借与恢复；借出和归还更新库存。
- 借期 30 天，符合条件时可续借一次、延长 15 天；借阅上限与限制条件按现有代码和测试核对。
- 预约排队、归还后分配保留副本、超时顺延、取消预约。
- 应还日当天不逾期，次日零点起按日计算，每天 50 分；归还时生成罚款，支持模拟缴费。
- 现有统计、CSV 持久化、旧账号密码验证。
- 保留现有 17 页导航：欢迎、登录、注册、管理员工作台、读者工作台、图书目录、我的借阅、我的预约、我的罚款、图书管理、新增图书、读者管理、借阅管理、办理借书、预约管理、罚款管理、统计报表。

旧 PRD 中的字典管理、完整图书字段、导入导出等设想不直接当作已实现功能。先建立“现有代码—业务规则—测试”对应表，再确定额外需求。

## 3. 实施顺序

### 第一步：统一约束与验收范围

- [ ] 建立唯一函数白名单：附录 C 66 个，正文补充 9 个，共 75 个函数名。允许出现不代表必须使用。
- [ ] 保留 ANSI 输出方案；中文统一 UTF-8，终端环境由外部配置，程序不调用 `system()`。
- [ ] 核对现有业务、页面与测试，记录缺失项，区分迁移任务与新增需求。
- [ ] 明确首版为单进程合规闭环；多终端自动刷新和并发写入仍是后续目标，不视为永久取消。

验收：约束无矛盾，业务范围和暂缓能力有记录。

### 第二步：先验证最难的交互

- [ ] 复用现有原型，去掉清单外函数，验证 ANSI 彩色、框线、定位和方向键。
- [ ] 验证禁用 `fflush()` 后，进入 `getch()` 等待前画面能否及时显示；未通过前不迁移全部页面。
- [ ] 实测中文姓名、书名输入，退格、左右移动、密码遮挡和超长内容处理。
- [ ] 分别验证菜单单键输入和表单文本输入；不能未经验证就把 `getch()` 输入字节直接当作 UTF-8。
- [ ] 采用固定 100×30 布局，外部说明窗口尺寸要求；暂不实现鼠标、滚轮和窗口自适应。

验收：在目标 Windows 终端完成键盘与中文输入输出演示，记录实际环境和限制。没有窗口尺寸查询能力时，不承诺自动检测过小窗口。

### 第三步：建立基础工具层

- [ ] 接入现有 `base_types.h`；不重复定义标准头已提供的类型和宏。
- [ ] 实现有容量检查的复制、拼接、整数解析和整数格式化，不把 `strncpy()` 机械替换为 `strcpy()`。
- [ ] 实现 UTF-8 解码、字符边界、显示列宽和安全截断，处理无效或不完整字节序列。
- [ ] 使用 `time()` 获取时间，自写日期解析、闰年、月份天数、日期加减和格式化；运行时按北京时间处理。
- [ ] 在目标工具链验证时间表示假设；业务日期计算优先采用日历日序号，避免把本地日期运算简单等同为固定秒数累加。
- [ ] 实现十六进制编码解码，供旧密码散列兼容使用。
- [ ] 修复 Makefile 的 shell 和测试路径问题，使构建、测试均可用明确的一条命令执行。

验收：关键工具覆盖容量边界、非法数字、中文截断、闰年、跨月、跨年及午夜边界；新增工具自身不调用清单外函数。

### 第四步：迁移数据与认证层

- [ ] 仓储字段由宽字符改为 UTF-8 字节串，按最大字节数重新确定容量。
- [ ] 保留五类 CSV 的字段顺序、UTF-8 BOM、中文状态值、引号与逗号转义，以及日期格式。
- [ ] 用旧数据副本验证读入、修改、保存、重新加载；不以字段变化后的整文件字节完全一致作为唯一标准。
- [ ] 保持旧密码的盐值解析、FNV-1a 常量、计算顺序和十六进制格式，验证旧账号仍可登录。
- [ ] 新盐按允许的 `rand()` / `srand()` 方案产生；仅作为课程演示方案，不宣称具备密码学安全性。
- [ ] 设计临时文件、备份、提交记录和启动恢复；检查写入及关闭文件的返回值。
- [ ] 验证 Windows 目标运行库的 `rename()` 行为，不直接等同于 `MoveFileExW` 替换语义。
- [ ] 针对一次借还涉及多个 CSV 的情况，验证中断恢复，避免库存与借阅记录只更新一半。
- [ ] 数据目录由启动脚本预建或随项目提供；不在 C 程序中使用禁用的建目录 API。

验收：旧账号可登录，新账号重启后仍可登录；数据兼容；模拟保存失败与重启后可以恢复到一致状态。

### 第五步：接入业务与界面

- [ ] 先交付“登录 → 查看图书 → 借书 → 退出 → 重启后记录仍在”的合规闭环。
- [ ] 闭环稳定后，逐步迁移归还、续借、预约、罚款、管理和统计页面。
- [ ] 统一标题、列表、分页、焦点、错误提示和状态栏；仅在可见状态变化时重绘。
- [ ] 首版通过 F5、进入页面及操作提交前刷新数据；操作时重新校验库存、读者状态和预约条件。
- [ ] 移植现有业务断言，核对角色权限、重复提交、库存边界和日期边界。

验收：先完成最小闭环，再逐页完成 17 页导航与全部现有业务回归。

- [ ] 为全部项目外部函数调用建立白名单核对，范围覆盖 `src/`、`include/`、`tests/` 和 `tools/`。
- [ ] 禁用函数搜索仅作辅助，不能只依赖旧正则；补查 `strpbrk()`、`mktime()`、`localtime_s()`、`difftime()`、`_wfopen()`、Win32 互斥与文件 API 等遗漏项。
- [ ] 全量构建在 `-std=c11 -Wall -Wextra -Wpedantic` 下零警告，移除 BCrypt 链接依赖。
- [ ] 测试命令一次跑完；测试用独立目录，目录准备和清理由外部脚本负责，C 测试代码也遵守白名单。
- [ ] 回归旧数据、中文输入输出、借还续借、预约、罚款、重启持久化及保存失败恢复。
- [ ] 在真实交互终端验证布局、中文、输入响应与频闪；保存实际验收记录。

验收：单进程合规版本完成，证据可重复；尚未完成的多终端能力明确标注。

## 4. 多终端专项：单进程闭环之后实施

原实现使用 Win32 等待超时产生一秒同步事件，使用命名互斥锁保护仓储写入。这两部分不能直接用阻塞式 `getch()` 与普通文件读写替换后就宣称等价。

- [ ] 分别验证无按键时自动同步和多个进程并发写入；手动刷新不等于自动同步。
- [ ] 不采用忙等 `time()` 循环模拟可靠的输入等待；不使用禁用的 `kbhit()`、`Sleep()` 或线程 API。
- [ ] 不把“检查锁文件不存在，再创建”视为可靠互斥，不把提交前重新读取视为完整并发保护。
- [ ] 在允许函数范围内验证可用的互斥、事务和异常恢复机制；没有可靠机制前，不开放多个写入进程。
- [ ] 测试两个终端同时借最后一本、同时注册相同账号、写入中断和崩溃后恢复。

若现有白名单与目标环境无法满足完整多终端目标，先形成实验结果和具体限制，再决定调整需求或申请函数例外；不预设已获例外许可。
