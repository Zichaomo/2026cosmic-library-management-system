## 启动问题的定位与验收

| 检查 | 证据与结论 |
| --- | --- |
| 不依赖本地脚本 | 导出当前索引的独立源码后，可完成编译和首次样例准备 |
| C 入口 | exe 的 PE CLR 目录为空；启动目标为 GCC 编译的 C 程序 |
| 原有数据 | `make prepare` 前后，原数据目录全部文件哈希一致 |
| 错误诊断 | 原环境出现整帧 6633 字节短写；诊断将打开、绘制、关闭阶段分开 |
| 编码复现 | 在 936 下出现相同乱码与输出失败；探针确认中文显示异常 |
| 修复验证 | 从 936 父环境调用新 `make run`，同条命令设置 65001 后，中文显示、管理员登录、Ctrl+Q 退出码 0 |
| 用户确认 | 用户在原 Conda/PowerShell 终端回复“这次可以了” |

最终保留正常整帧输出、同 cmd 设置代码页和必要的错误诊断。`CONOUT$` 通过允许的文件函数输出，不调用 C 的 `system`、Win32 设置函数或外部启动器。纯 C 探针 `make diagnose-console` 只测试输出，在 `build/` 下写独立测试文本，不访问图书馆数据。

## 历史结果的适用范围

旧的 454 项包含迁移 66 项和历史参照 91 项，以及外部环境专项；不是现行 `make test` 的计数。旧 C 测试源码仍保留，完整前置样本由当时的本地工具准备，不把缺少这些条件的手动运行当作等价验证。

迁移阶段曾验证旧账号导入、反向读取、多行 CSV、文件锁造成的导出失败及快照中断恢复。这些是已有设计证据，不代表支持并发业务或断电恢复。
