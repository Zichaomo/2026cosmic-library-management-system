## 合规核对范围与证据

- tools/audit_source.py（本地保留、已取消跟踪）自动枚举 src/、include/、tests/、tools/ 下所有 .c/.h，当时 **29 个文件**，不使用硬编码源文件清单遗漏新文件。
- 75 项白名单与课程清单一致；允许的头文件为 stdio/string/ctype/math/malloc/conio/stdlib/time。带引号的本地 include 必须解析到本次活动清单。
- 去除注释与字符串后识别调用，只有实际函数体才授予项目函数身份；普通 extern 声明不能把外部函数变成自写函数。简单函数别名仅在目标已知时接受；宏体仍检查。内置反例验证 snprintf 声明、调用和宏内 localtime_s 不会静默放行。
- 本轮显式库调用共24种：fclose、ferror、fgetc、fgets、fopen、fprintf、fputc、fputs、fread、free、fseek、ftell、fwrite、getch、printf、rand、realloc、rename、rewind、srand、strcmp、strlen、strstr、time。逐文件结果写入 build/source-audit.json。
- 辅助搜索复核 strpbrk、mktime、localtime、difftime、_wfopen、Win32、wchar、fflush、snprintf、memcpy、memset、Sleep、kbhit、system 等；活动 C 实现无上述依赖。唯一 BCrypt 文本是测试断言描述，不是调用。
- 当前应用和当前 C 测试均以 `-std=c11 -Wall -Wextra -Wpedantic -Werror` 构建通过。objdump -p 检查新 exe，仅 KERNEL32.dll、msvcrt.dll 导入，无 BCrypt.dll；KERNEL32 是工具链/CRT 依赖，不能把整个 PE 的导入表误当应用显式 API 调用。

检查器是针对当前源码写法的词法核对，不是完整 C AST/任意预处理条件的形式证明。实际源码复核、严格构建及链接检查共同补充；未来引入函数指针、复杂宏或新的平台分支时须扩展检查。

legacy/ 不属于合规应用；build/ 下生成的旧兼容 oracle 也不属于应用。PowerShell/Python 是外部启动、目录准备、测试和制图工具，包含 .NET/系统调用不意味着 C 获得同样函数许可。tools/ 下的原型 C 和 C 测试仍纳入同一白名单，未通过扩展名豁免。
