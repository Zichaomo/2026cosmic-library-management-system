# 多终端可行性实验

**当前状态：实验目标已移除。** 旧的 `make test-concurrency` 目标依赖本地 Python 驱动（多进程、管道、线程、kill），这些驱动已从仓库取消跟踪，Makefile 不再提供该目标。C 探针 `probe.c` 仍保留在本地源码中，但未纳入 `make` 构建，也不进入应用。

实验方法与完整结论见[多终端可行性记录](../../docs/多终端可行性记录.md)。结论没有变化：

- 普通 `fopen` 的 wb 模式不互斥，24 个进程全部成功打开；
- 当前目标 msvcrt 的 wx/wbx/w+bx 连新文件也拒绝，x 模式不可用；
- rename 竞争能产生“1 成功、23 拒绝”，但进程退出会遗留占位，缺少经过验证的所有者与恢复协议；
- 阻塞 `getch()` 无输入时不返回，无法据此做无按键自动刷新。

因此应用保持单进程，多个写入者仍不支持；单实例由使用者人工保证——旧的启动器独占句柄已随启动器一并取消。

如需复现，可自行编译 `probe.c`（课程白名单内的 C 探针）并在独立空目录运行；多进程竞争部分需要外部驱动，不属于本仓库的纯 C 交付内容。实验只在 build/concurrency/run-GUID 下的空文件上进行，不访问应用 CSV。
