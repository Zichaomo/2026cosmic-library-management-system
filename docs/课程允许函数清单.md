## 7. 清单外的高频函数（重构时必须替换）

以下函数是 C 语言里很常用、但**不在附录 C 中**的，重构时一律要替换或自己手写：

| 分类 | 清单外的函数 | 替代思路（仅用清单内函数） |
| --- | --- | --- |
| 格式化到字符串 | `sprintf` / `snprintf` / `vsnprintf` / `asprintf` | 直接 `printf` / `fprintf` 输出；需要拼串时用 `strcpy` + `strcat` 手工拼 |
| 有界字符串 | `strncpy` / `strncat` / `strncmp` / `strtok` / `strdup` / `strrev` | 自己写循环；用 `strcpy` + `strlen` 控制长度 |
| 内存块 | `memcpy` / `memset` / `memmove` / `memcmp` | 自己写 `for` 循环逐字节处理 |
| 转换 | `atoi` / `atof` / `strtol` / `itoa` | 自己写数字解析与格式化循环（配合 `isdigit`、`pow`） |
| 字符串输入 | `sscanf` | `scanf` / `fscanf`（清单内），或按字符 `getchar` 解析 |
| 缓冲与退出 | `fflush` / `exit` / `abort` / `atexit` | `return` 逐层返回；写文件用 `fclose` 收尾 |
| 随机数 | `srand` / `random` | 只用 `rand`（清单内） |
| 排序查找 | `qsort` / `bsearch` | 自己写冒泡/插入排序与线性查找 |
| 时间日期 | `time` / `localtime` / `strftime` / `clock` | **清单内没有任何时间函数**，需由用户输入或从文件读取日期，自己做闰年/月份天数计算 |
| 平台扩展 | `<windows.h>` 全部（`SetConsole*` / `GetConsole*` / `ReadConsoleInput*` / `Sleep` …）、`<conio.h>`（`getch` / `kbhit` / `gotoxy` / `textcolor`）、`<wchar.h>`/`<wctype.h>`（`wcs*` / `swprintf` / `wprintf` …）、`<bcrypt.h>`（`BCryptGenRandom`） | 一律禁用；控制台输出只用 `printf`/`puts`/`putchar`，输入只用 `scanf`/`gets`/`getchar` |

## 8. 已定口径与遗留边界

1. **【已确认可行 · 2026-10-16】ANSI 转义序列**：用 `printf` 打印 `"\033[2J"`（清屏）、`"\033[31m"`（红色）、`"\033[10;20H"`（定位）来控制画面，**保留彩色 TUI**。理由是它输出的是**字符串**、不是库函数，不违反「只用书中函数」；依赖终端支持 VT（Windows Terminal、VS Code 终端默认支持，旧版 conio 窗口需先开启）。
2. **【已定方案 · 2026-10-16】类型头文件自己写一套**：不再包含 `<stdbool.h>` / `<stdint.h>` / `<stddef.h>` / `<limits.h>` / `<errno.h>`，改为项目自己的 typedef / #define（详见下一节「自写类型定义方案」）。typedef 与 #define 是 C 语言本身的特性，不是库函数调用，因此不违反课程口径。
3. **`gets`**：附录 C 里虽然列有 `gets`，但 C11 起已从标准中移除，GCC 会告警。是否允许改用同为附录 C 内的 `fgets`，需老师确认。
4. **中文显示与中文输入**：清单内没有宽字符函数，纯 `printf` 输出中文依赖控制台代码页（UTF-8 / `chcp 65001`）；`getch()` 按字节读取，中文输入需要一个字符一个字符地拼字节。字号、对齐与输入方案建议与老师确认后再定界面观感。
5. ~~`rand` 的取值范围~~ **已澄清**：附录 C 表 C-1 印的「−90～32767」是原书排印错误。正文第 64 页写明「`rand()`：该函数产生一个 **0～32767** 之间的随机数」，以正文为准。

## 9. 自写类型定义方案（2026-10-16 在本机 w64devkit / GCC 16.1 实测）

**结论：可行，而且有一半根本不用写 —— 允许的 `<stdio.h>` 已经把它们带进来了。**

### 9.1 不用自己写、直接用（随 `<stdio.h>` 间接提供）

在只包含 `<stdio.h>` `<string.h>` `<ctype.h>` `<math.h>` `<malloc.h>` 的情况下，编译器已经定义了：

| 符号 | 来源 | 项目现用量 |
| --- | --- | --- |
| `size_t`、`FILE` | `<stdio.h>` → `stddef.h` | `size_t` 203 处、`FILE` 19 处 |
| `NULL` | 同上 | 多处 |
| `INT_MAX`、`CHAR_BIT` | `<stdio.h>` → `limits.h` | `INT_MAX` 2 处 |
| `EOF`、`SEEK_SET` | `<stdio.h>` | 6 处 |
| `SIZE_MAX` | `<stdio.h>` | — |

> ⚠️ **千万别重复定义这些**：本机实测 `typedef int size_t;` 会直接报 `error: conflicting types for 'size_t'`（因为 `<stdio.h>` 已经定义过；C11 只允许"同类型"的重复 typedef）。

### 9.2 需要自己写（推荐单独放一个头文件，如 `include/base_types.h`）

```c
#ifndef BASE_TYPES_H
#define BASE_TYPES_H
/* 本文件只做类型与宏定义，不调用任何库函数：
   typedef 与 #define 属于 C 语言语法，不属于课程限制的"库函数"。 */

typedef int bool;          /* 替代 <stdbool.h> */
#define true  1
#define false 0

typedef unsigned char      u8;   /* 替代 <stdint.h> 的 uint8_t  */
typedef unsigned short     u16;  /* 替代 uint16_t（项目现用 1 处） */
typedef unsigned int       u32;  /* 替代 uint32_t */
typedef unsigned long long u64;  /* 替代 uint64_t（项目现用 5 处） */

/* size_t / NULL / INT_MAX / EOF / FILE 由 <stdio.h> 提供，此处不要重复定义 */
#endif
```

对应改动量：`bool` 193 处、`true` 102 处、`false` 214 处可以原样保留（只要包含这个头文件）；`uint64_t` 5 处、`uint16_t` 1 处改名为 `u64`/`u16`。

### 9.3 三条注意

1. **不要用 `<stdbool.h>`**：它的 `#define bool _Bool` 会和自写的 `typedef int bool` 打架。
2. **定宽类型建议改用自己的名字**（`u32`/`u64`），不要继续叫 `uint32_t`：万一将来某个允许的头文件间接拉进 `<stdint.h>`，不同类型会报错、同类型在 C11 才勉强允许。
3. **`errno` 建议放弃**：它其实也随 `<stdio.h>` 来了（展开为 `(*_errno())`），但出自 `<errno.h>`，口径上不干净；错误处理改成看返回值 / `NULL` / `feof()` / `ferror()` —— 后两个正好都在白名单里（`ferror` 见第 0.5 节）。项目现用 `errno` 7 处。

> 顺带：`wchar_t`（项目现用 283 处）属于 `<wchar.h>` 的世界，**不是类型头能解决的**，必须整片改写成 `char` 字节串处理。
