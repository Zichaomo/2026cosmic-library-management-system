## 实际兼容证据

外部脚本在 build/ 中生成一个只调用原有仓储和认证的参照程序，并编译链接未经修改的旧代码。它使用旧 BCrypt 随机盐注册账户，生成带逗号/引号的中文姓名、图书、已归还借阅、已缴罚款与待取预约等五类实际 CSV。

新实现导入这些文件后，验证旧中文密码、错误密码和含补充平面字符的密码；随后注册新读者、保存、重新加载。再让旧实现读取新导出的五表，旧账户和新账户都能登录。

未把真实运行 CSV 复制到测试目录；样本由旧实现独立生成。脚本同时比较运行前后的真实 data/*.csv 文件哈希，已有文件保持不变。新进程单独验证已注册账户可登录，避免只用同一进程内存证明持久化。

## 异常与中断验证

| 场景 | 结果 |
| --- | --- |
| 非法引号、非法 UTF-8、超长字段 | 拒绝，不截断为另一条合法记录；解析输出保持原值 |
| 引号中 CRLF、末尾空字段、无行尾 EOF | 正确读取，转义写回后字段值一致 |
| 注册参数不合法、重复账号、管理员编号 | 不增加内存记录，不提交 |
| 打不开快照目标 | 注册撤销内存新增，保留已有提交 |
| 快照数据已写但提交尾记录未写时中断 | 仓储阻止继续操作；重新打开使用上一完整代次 |
| 快照已验证提交、CSV 尚未更新时中断 | 返回“已提交待导出”；重启恢复新账号和五表 |
| 第一张 CSV 导出后中断 | 从同一全表快照恢复五张 CSV，无部分代次混合 |
| 库存超过总数、悬空图书引用、重复 ID、非法盐 | 提交前拒绝，不损坏已提交快照 |
| 最新快照损坏 | 回退前一完整代次，设置 recovered，保留跨表一致性；需提示最新代次可能丢失 |
| 两份快照都损坏 | 停止，不能把 CSV 当成可靠替代来源 |
| 数据目录未准备、表头错误 | 停止，不自动建空库 |
| Windows 独占锁住 books.csv | 实际导出失败，启动恢复停止；解除锁后恢复成功 |

故障注入用来验证确定的代码边界，没有将其冒充为真实断电实验。真实 Windows 文件锁是外部 .NET 打开的独占句柄，C 实现仍只使用允许的 fopen 等函数。

另在目标 CRT 实测：`rename` 不能替换已有目标，重命名至不存在目标成功。因此实现没有用它冒充旧 MoveFileExW 的覆盖行为；采用非活动槽写入、提交尾记录和全表重放。
