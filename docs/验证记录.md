## 启动与终端修复

1. 从Git索引导出不含本地脚本的独立源码，make编译和make prepare首次生成七个数据文件、样例成功。PE的CLR目录为空，入口是原生C exe。
2. 纯C启动调整时，原build/library-data全部文件在make prepare前后哈希一致。
3. 用户报告make run的run-compiled Error 1。代码核对显示退出1来自终端绘制路径，数据/时间加载失败退出3。原stderr输出失败会被退出备用屏幕遮去详情。
4. 本机常规PowerShell可启动，未声称完整复现用户环境。额外构造stderr不可写（cmd的2>&0）时，旧程序退出失败；改用CONOUT$逐帧输出并关闭后，同条件下make run成功显示、登录管理员、Ctrl+Q退出0。
5. 修复后另在普通Windows PowerShell会话执行chcp 65001和make run，显示、管理员登录、Ctrl+Q退出0均通过。
6. 帧写入、关闭或恢复失败现在会在退出备用屏幕后向stdout输出英文故障提示。未用Win32、fflush、system或外部启动器兜底。

ConPTY工具窗口用于键盘和退出码检查，不冒称用户120×35终端、字体、真实输入法已验收。用户实际Conda/PowerShell环境仍需重试确认；若仍失败，以新提示和退出码继续定位。
