# 编译、运行与问题排查

## 环境与入口

Windows GCC/MinGW、GNU Make加入PATH；本机工具链为D:\w64devkit\w64devkit\bin。使用支持ANSI真彩色的Windows Terminal，手动保证可见区域至少120列×35行。在项目根目录执行：

```text
make run
```

Makefile在同一条cmd命令中先执行chcp 65001再立即启动C程序；不要依赖在PowerShell中提前单独执行chcp后仍能保持相同运行时编码。该环境准备命令不由C调用，也不使用PowerShell脚本。当前程序使用getch读取UTF-8字节；默认非UTF-8代码页可能导致中文输入错误。终端字体、输入法和窗口由用户设置，程序不自动检测尺寸。

| 命令 | 作用 |
| --- | --- |
| make | 严格C11编译到start/CosmicLibrary.exe |
| make run | 编译、准备首次数据后直接运行C程序 |
| make run-compiled | 使用已有C exe，准备首次数据后运行 |
| make prepare | 仅在目标目录不存在时准备空模板并用C生成样例 |
| make diagnose-console | 比较ASCII、中文、框线和ANSI在不同标准文件输出方式下的结果，不访问运行数据 |
| make test | 运行当前297项C断言和新进程持久化检查 |
| make clean | 仅提示；不删除运行数据或exe |

start/CosmicLibrary.exe就是C主程序，不是C#启动器。它需要数据参数，不能无参数双击进入。已有数据时可从项目根目录执行：

```text
cmd /d /c "chcp 65001 >nul && start\CosmicLibrary.exe --data build/library-data"
```

## 数据和演示账号

默认build/library-data保留之前进度。新目录样例为admin/admin123、reader001/reader123，以及20种图书各3册；旧目录以其已有账号和记录为准，不重置。

教材函数范围没有创建目录的函数，因此Makefile在运行前用cmd内建mkdir/copy复制resources/empty-data/七个格式文件，再调用C程序--seed-demo。目录已存在时不会重新初始化，缺文件、权限不足、损坏会失败，不自动补空库。

独立演示可用make run DATA_DIR=build/demo。请使用简单的相对ASCII路径，不含空格或命令字符。数据父目录可中文，实际传给窄字符文件接口的目录参数用ASCII。不要把data/旧文件直接覆盖到已建立快照的目录，不要直接删除build/。

单进程由使用者人工保证，同一数据目录只开一个实例；已取消外部单写者保护。保存恢复机制见[架构与数据](架构与数据.md)。

## 终端输出与错误

当前每帧用fopen("CONOUT$","wb")打开Windows控制台设备，fwrite输出并fclose确认落入输出流；关闭帧文件可刷新缓冲，无需fflush。备用屏幕的进入/恢复也走该设备。CONOUT$是Windows设备文件名，不是新的库函数；不调用Win32、system、Python或PowerShell。交互必须在真实控制台中运行，不能用无控制台的后台进程代替。

实际故障已定位并获用户确认：用户终端的程序运行时回到936，UTF-8中文出现“涓枃…”乱码，框线写入失败。受控936环境复现了同样的expected=6633/written=480/close失败；单独提前chcp不能保证启动子程序时编码保持。最终将chcp 65001与exe放在同一条cmd命令，用户确认可以进入。大帧/分块修改本身不是这次问题的根因修复，最终保留正常整帧输出。继承stderr不可写是另一个已覆盖的输出失败场景。

| 程序退出码 | 排查方向 |
| --- | --- |
| 1 | 控制台打开、绘制或关闭失败；现在会在退出备用屏幕后输出Console output failed、Stage和Renderer数字；ferror的32是非零错误标志，不是errno编号 |
| 2 | 参数缺失或不合法；确认在项目根目录运行make run |
| 3 | 当前时间或数据加载/恢复失败；保留数据目录，检查七个文件、权限与快照，不删库重试 |
| 4 | 显式--seed-demo失败；不对已有数据重复初始化 |

Make还会把子程序非零退出包装成自身的Error 2，要先看子程序的消息和错误码。若编译提示exe被占用，请先正常退出实例再编译，不强杀或重置数据。缩放后按F5刷新，静置时不会自动检测窗口变化。
