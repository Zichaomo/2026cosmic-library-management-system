# 运行说明

更新：2026-10-23。

## 环境与启动

需要 Windows GCC/MinGW、GNU Make，以及支持 ANSI 真彩色的终端。将 `gcc`、`make` 加入 PATH，手动调整可见区域至至少 **120 列 × 35 行**。本机工具链位于 `D:/w64devkit/w64devkit/bin`，其他机器可使用自己的安装路径。

在项目根目录执行：

```text
make run
```

Makefile 在同一条 cmd 命令中执行 `chcp 65001` 后立即启动 C 程序。提前在 PowerShell 中单独执行 `chcp`，未必能保证子程序启动时仍保持 UTF-8；推荐使用上述入口。

| 命令 | 作用 |
| --- | --- |
| `make` | 严格 C11 编译到 `start/CosmicLibrary.exe` |
| `make run` | 编译、首次准备数据并运行 |
| `make run-compiled` | 使用已有 exe，首次准备数据后运行 |
| `make prepare` | 仅准备不存在的目标数据目录和样例 |
| `make test` | 执行当前 C 测试及新进程持久化检查 |
| `make diagnose-console` | 检查代码页、ASCII、中文、框线和 ANSI 输出 |
| `make clean` | 只显示说明，保留数据和编译产物 |

`start/CosmicLibrary.exe` 就是 C 主程序，需要数据目录参数。已准备好数据时，可在项目根目录执行：

```text
cmd /d /c "chcp 65001 >nul && start\CosmicLibrary.exe --data build/library-data"
```

不支持无参数双击进入，不使用外部启动器。

## 数据目录与账号

默认目录为 `build/library-data`。新目录提供管理员 `admin/admin123`、读者 `reader001/reader123`，以及 20 种图书、每种 3 册。已有目录使用原有账号和记录，不重复生成样例。

教材函数范围没有创建目录的函数，因此 Makefile 在首次运行前用 cmd 的 `mkdir`/`copy` 复制 `resources/empty-data/` 中的五张空 CSV 表头和两个 `EMPTY` 快照标记，再调用 C 程序的 `--seed-demo` 生成样例。已有目录不重新初始化；必要文件缺失、损坏或不可读时停止，不补空库覆盖。

创建独立演示目录：

```text
make run DATA_DIR=build/demo
```

目录参数使用简单的相对 ASCII 路径，不含空格或命令字符；项目工作目录本身可以有中文。原始 `data/` 不作为默认运行目录。

同一数据目录只开一个实例，当前没有自动互斥保护。保留 `build/library-data`，不要清空 `build/`；建立快照后不要直接编辑导出 CSV。保存与恢复机制见[架构与数据](架构与数据.md)。

## 窗口与退出

Tab/方向键切换，Enter 确认，F1 帮助，F5 刷新，Ctrl+Q 退出。缩小再放大后按 F5 补画；程序不在无按键时自动检测窗口尺寸。

编译提示 exe 被占用时，先正常退出该程序再执行 `make`。不要强杀实例或删除数据来解决编译占用。

## 错误处理

| C 程序退出码 | 含义与处理 |
| --- | --- |
| 1 | 控制台打开、绘制或关闭失败；保留 `Stage`、`Renderer` 输出，运行 `make diagnose-console` 排查 |
| 2 | 启动参数缺失或错误；使用项目根目录的 `make run` |
| 3 | 当前时间或数据加载/恢复失败；保留现场，核对文件、权限与快照 |
| 4 | 显式 `--seed-demo` 未完成；不要对已有数据重复初始化 |

Make 自身还可能显示 `Error 2`，应先检查子程序的提示和退出码。`ferror` 的非零值只表示输出流出错，不能直接当作系统错误编号。

此前的启动失败已在代码页 936 下复现，设置 65001 后通过，并获用户在原终端确认。当前启动命令将编码设置和程序启动放在同一条 cmd 命令，证据见[验证记录](验证记录.md)。
